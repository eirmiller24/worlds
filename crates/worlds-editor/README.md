# worlds-editor

The Worlds desktop editor, binary `worlds`. eframe + egui_dock for the shell, a custom wgpu pass for the map.

```sh
cargo run -p worlds-editor --release -- path/to/game.worlds
```

With no argument, open a project with Ctrl+O (native folder picker via `rfd`).

## Screenshots without a window

```sh
worlds --screenshot out.png [--level <slug>] [--size 1600x900] [--zoom N] \
       [--hover X,Y] [--tool brush] [--script edits.json [--save]] [--rule <layer>/<rule>] \
       [--synthetic 500] [--synthetic-entities 100] [--synthetic-notes 500] [--synthetic-guides 2000] \
       [--bench 300 [--bench-palette QUERY]] \
       [--serve [--wait-for SECONDS]] [--autosave SECS] \
       [--recover keep|apply|discard|ask [--recover-conflicts]] [--recover-report r.json] <project dir>
worlds [--autosave SECS] [--recover keep|apply|discard|ask [--recover-conflicts]] <project dir>   # the window
worlds --screenshot out.png --snapshot (--level <slug> | --world-rect X,Y,W,H) \
       [--max-size 1024x1024] [--layers a,b] <project dir>
```

This creates its own wgpu device (no window and no display, so no `xvfb-run` needed), runs four frames of the real editor UI into an offscreen texture (five with `--zoom`, so the status bar's pointer readout, drawn before the map in a frame, is the zoomed one) and writes the last one. The image has the whole UI in it, with the viewport's paint callback running inside egui-wgpu's render pass just like in the window. Exit code 0 on success.

- `--level` makes that level active and frames it; without it the whole world is framed.
- `--zoom N` steps N zoom notches in (negative = out) after framing.
- `--hover X,Y` puts the pointer there (screen points), which fills in the status bar readout and draws the tool preview. `--tool` picks the tool.
- `--script FILE` runs a JSON list before rendering. Each item is a command in the [`docs/commands.md`](../../docs/commands.md) wire format (applied as its own undo entry, exactly like an inspector edit; rule edits too: `set_rule`, `move_rule`, `set_macro`, ...), a tool gesture replayed through the same path the mouse takes, or a UI step (`src/script.rs` has the details):

  A `ui` step changes no document; its `ui` key says which kind, and each kind refuses keys it doesn't know. `"ui": "rules"` opens the Rules pane on auto layer `layer`, makes `level` active and frames it, and selects `rule` (an inline rule, a template reference, or an expanded `<reference>__<rule>`, whose reference is then shown opened in the list) and scrolls the list to it, with its `Pass n` and group headers above it (a list that already shows them doesn't move), so the picture shows the pane and the rule's highlight on the canvas. `level`, `rule`, `group_collapsed` (groups shown collapsed), `show_regions` (the pane's "Show regions" toggle, on by default) and `show_occupancy` ("Show occupancy", off by default) are optional. An unknown layer, level or rule, or a layer that isn't auto, is an error naming it. `"ui": "layers"` sets the Layers pane: `active` (a layer slug made active), `visible` (`{ slug: bool }`), `opacity` (`{ slug: 0..1 }`, the view opacity); every key optional, an unknown layer or an opacity outside 0..1 is an error and nothing changes. `"ui": "project"` brings the Project pane to the front (see "The Project pane"): `add_layer` (`int_grid`, `tiles`, `auto` or `entities`) does what its + Layer menu does (one entry; the new layer active, its form open), `add_tileset` (a PNG path, relative to the current directory) what + Tileset… does with that file (one entry, its form open; an image outside the project is copied into `art/` right away, the one file a run without `--save` writes, since an image isn't part of the document), then `section` (`layers`, `tilesets`, `settings`) shows that part and `layer` / `tileset` open that form; every key optional, and an unknown kind, section, layer or tileset, an unreadable image or a refused add is an error. `"ui": "palette"` shows the entity palette (the active entities layer, else the first, becomes active; the Palette tab comes to the front) and replaces the parts of its state it is given: `search` (the search text), `favorites`, `recent` (most recent first, at most 8), `collapsed` (parts `/favorites`, `/recent`, `/level`, `/catalogue` and category paths such as `Puzzle/Doors`), `chips` (tag filter), `view` (`"grid"` or `"list"`), `brush` (a type slug); `"tool": true` switches to the entity tool; `"enter": true`, applied after the other keys, does what Enter in the search box does (`entities::enter`): the first hit for the search becomes the brush and the entity tool is on, so a following `entity` gesture without `type` places it (a search with no hit is an error naming it). An unknown type is an error. `"ui": "select"` (`entities`: ids) selects those entities exactly as `view.select` does (every one selected, the first primary, its level made active) and also frames that level and brings the Inspector to the front; an unknown id is an error naming it. `"ui": "types"` opens the Types pane on an entity type (`"entity": slug`) or on the level fields (`"level_fields": true`), exactly one of the two, and with `"field": slug` opens that field's form (the type's own form folds away and the field form scrolls into view); an unknown type or field is an error.

  `brush` sets the layer's palette brush before the gesture: an int_grid value by slug (`"solid"`), `"erase"` (paint empty with any painting tool, on int_grid or tiles layers; on a derived layer it removes overrides), `"suppress"` (derived layers only: override to empty, `"!"`), one atlas tile `{ "tileset": ..., "tile": [col, row] }`, a stamp `{ "tileset": ..., "rect": [col, row, w, h] }`, or a random brush `{ "tileset": ..., "tiles": [alternatives] }` (the alternatives in the forms of a rule's `out.tiles`: `[col, row]`, `[col, row, w, h]`, `{ "rect": [...], "weight": n }`, `{ "stack": [[col, row], ...], "weight": n }`; see "Random and scatter brushes"). The three tile forms also take `"density": 1..100` (the Paint strip's density, which stays set) and `"seed": n` (a fixed seed for the strokes' randomness from then on, so a test gets the same picks every run). Leave `brush` out to keep the current brush; `null`, an unknown slug or tileset, or a form that doesn't fit the layer (a tile on an int_grid layer) is an error naming the problem.

  A gesture makes its level and layer active, sets the brush if given, then sends `Begin` at the first cell of `path`, a `Move` per later cell and `End` at the last (`"cancel": true` sends Escape instead). `shift`, `alt` and `handle` (select: resize instead of move) are optional. A `select` gesture grabs the level body unless it has `handle`, or `"press": true`: then the press decides what it grabs exactly as a mouse press does (`viewport::select_press`): an entity under the first cell is selected (with `ctrl`, added) and the drag moves the selection; empty space in the level is a marquee; `ctrl` also makes the move by pixel. An `entity` gesture (the entity tool) defaults to the active entities layer, else the first; `type` and `fields` (each must be a field of the type) set the entity brush first (`fields` alone keeps the brush's type), and `ctrl` holds Ctrl (pixel placement; the pointer is in the middle of each cell). `type` and `fields` on another tool's gesture are an error, and so are `ctrl` on a gesture that isn't entity or select and `press` on one that isn't select. A failing command, or a gesture that leaves an error in the status bar (painting a locked layer), stops with exit code 1.

  Ctrl-D and Delete are the `duplicate` and `delete` steps.
- `--synthetic-notes N` adds N world pins over the world's bounding box (icons cycling through the built-in ones), ⌈N/4⌉ notes in every level and N/10 four-point world paths (`doc::synthesize_notes`); `--synthetic-guides N` adds N four-point guide polylines, every other one in the guide group `syn_shifted` (two cells down) (`doc::synthesize_guides`). Both are deterministic and make the project refuse `--save`. `--bench 300 --synthetic-guides 2000 --synthetic-notes 500` at 1600x900 (world framed, release, Intel UHD 630): `ui_ms` p50 / p95 / max 2.9 / 5.4 / 6.4 and 2.7 / 5.6 / 7.7, `total_ms` 8.5 / 12.1 / 13.4 and 7.9 / 12.3 / 14.3 (two runs, load 6).
- `--rule <layer>/<rule>` is the same as a final `{ "ui": "rules", "layer", "rule", "level": <--level> }` step after the script. The window takes it too (applied once the project is open).
- `--save` saves the project after the script (`save_dirty`: only the touched files); with `--serve`, after serving.
- `--serve` hosts the live API exactly as the window does (see "Live API"), prints `{"port": .., "pid": .., "project": ".."}` as one JSON line on stdout, then keeps rendering frames (about 60 a second, each one a drain point) for `--wait-for SECONDS`, or without `--wait-for` until stdin closes. Then it saves (with `--save`) and takes the screenshot as usual. This is how a test runs `worlds-mcp` against a real editor process with no window; `.worlds/server.json` exists while it serves and is removed on exit.
- `--snapshot` draws the map alone, with no UI (no panels, toolbar, grid, outlines or tool preview), through the same function as `view.snapshot`, [`SnapshotRenderer::render`](src/snapshot.rs), so the same arguments give the same pixels. `--level <slug>` frames that level, `--world-rect X,Y,W,H` that rect of world pixels (one of the two is required). `--max-size WxH` (default `1024x1024`, `view.snapshot`'s `size` default) bounds the image: the scale is the largest that fits, a whole number when it is 1 or more. `--layers a,b` draws only those layers (default: every layer, the `view.snapshot` rule for a fresh view). Entity boxes are drawn, and annotations (every guide as built; open notes, pins, paths and regions; no tag filter: a snapshot is the data, not the view). An unknown level or layer, or a bad rect, exits 1 with the reason.
- `--synthetic N` grows the project to N levels by copying its levels into a grid (perf testing; also works in the window).
- `--synthetic-entities N` adds N entity types `syn_<i>` (`doc::synthesize_entities`): a three-level category tree from fixed word lists (6 x 4 x 3), 1 to 3 tags from a pool of 12, icons cycling through the first tileset's atlas (tiles with at least 10% of their pixels opaque, so no icon is near-blank; any drawn tile if none is), hashed colors, 3 to 14 fields per type cycling through every field type and its array form (int and float with bounds, bool, string with a regex, text, color, enums from the project enum `syn_kind` (added) and inline values, point, entity_ref with `allowed_tags`, path, tile, json), and ⌈N/4⌉ instances per level on the first entities layer at in-bounds cells. Every choice and id comes from a fixed seed, so the same project and N give the same bytes. It combines with `--synthetic` (levels first). Either flag makes the project refuse to be saved (`--save`, Ctrl+S, `project.save`).
- `--bench N` renders and times N more frames while the camera pans in a circle, then prints `ui_ms` (the editor's `frame()` CPU time) and `total_ms` (the whole frame including tessellation and the GPU) as mean, p50, p95 and max, plus single-chunk rebuild times. With `--bench-palette QUERY` the camera stays still, the entity palette is shown, and frame *i* types the first `i % len + 1` characters of QUERY into its search (so the rows are rebuilt every frame).
- `--autosave SECS` autosaves unsaved edits every SECS seconds (`0`: off). Default: `WORLDS_AUTOSAVE_SECS`, else 30 s in the window and off with `--screenshot` (which writes nothing without `--save`). See "Autosave and crash recovery".
- `--recover MODE` decides about an autosave a previous session left without asking: `keep` (the `--screenshot` default: open from disk, leave it, print one `autosave: … not applied` line on stderr), `apply` (recover it; files changed on disk since are skipped unless `--recover-conflicts`), `discard` (move it to `.worlds/autosave.discarded/`) or `ask` (the prompt, the window's default; with `--screenshot` it is in the picture). `--recover-report FILE` writes what was found as JSON: `{ "found", "session": { pid, written, last_label, generation }, "files": [{ path, state, conflict, plus, minus, diff }], "applied": [paths] }` (`{ "found": false }` when there was none; `{ "found": true, "broken": "..." }` for an unreadable one; `{ "found": true, "unreadable": "..." }` when a project file it covers can't be read to compare, and the autosave is kept). `apply` that finds an unreadable autosave, or can't compare it, exits 2, as does `apply` on a filesystem that can't lock (no autosave or recovery there). The report body (with every file's diff) is only made when `--recover-report` is given.
- `WORLDS_FALLBACK_ADAPTER=1` forces the software adapter (llvmpipe). Without it, any adapter is used and the fallback is tried if none is found.

In headless mode nothing is written into the project unless `--save` is given (no `.worlds/ui.json` either, and only a `"ui": "project"` step's `add_tileset` copies an image from outside into `art/`; a run that edits, with `--serve`, `--save`, `--recover`, `--autosave` or a `--script` with `WORLDS_AUTOSAVE_SECS` set, takes the session lock `.worlds/editor.lock` and exits 2 with "this project is open in another Worlds (pid N, since …)" when another editor holds it), bakes run synchronously (including the per-layer rebakes after a rule edit, so the picture is complete), and there is no per-frame rebuild budget.

Running the real window under Xvfb: winit needs `libxkbcommon-x11.so`. Where the system has none (some containers), symlink a copy into a directory and point `LD_LIBRARY_PATH` at it: `env -u WAYLAND_DISPLAY LD_LIBRARY_PATH=<dir> xvfb-run -a worlds <project>`. Xvfb has no window manager, so the window never gets keyboard focus on its own and every key sent to it (`xdotool key`, ...) is dropped: focus it first (`xdotool search --name Worlds windowfocus`, or run a window manager in the Xvfb session).

Tests and local runs write reference shots to `crates/worlds-editor/screenshots/` (not tracked).

## Using it

| Input | Does |
| --- | --- |
| Wheel | zoom to cursor, through fixed steps from 1/256 (0.39%) to 1600% (integers above 100%, so pixel art stays crisp). Fit world (Shift+F, Home), Fit level and `view.focus` pick the largest step that fits, or, for a world too big for 1/256, the exact zoom that fits it (an off-grid zoom); from there the wheel steps in to the nearest step and out not at all |
| Middle or right drag, Space + left drag, Hand tool (H) | pan |
| Right click | context menu: New level here, Frame, Delete, Crop to content. A map with no level says so in a card in its middle: right-click for New level here…, or Ctrl+P, New level… (and, with no layer either, that layers and tilesets are set up in the Project tab) |
| N | the Note tool: an options strip at the top left of the map picks the kind (Note, Pin, Path, Region), the scope (Auto: the level under the press, else the world; World: always world scope) and a pin's icon. A click adds a note ("Note") or a pin ("Pin", the strip's icon) and selects it, the Inspector's title focused (the Inspector comes to the front, the title selected, so typing replaces it; the keys typed are the title's, never tool shortcuts); Path: clicks add vertices, Enter or a double click finishes (2+ points), Backspace drops the last vertex, Escape cancels; Region: a drag over 4 screen px is a rect, clicks with Enter or a double click a polygon (3+). Points snap to half the project grid (Ctrl: the pixel). While drawing, the segment and total length (px and tiles), dx and dy show by the pointer and in the status bar. Each annotation is one `add_note` entry |
| M | the Measure tool: the Path gesture with the same readout, never an entry; the measurement stays drawn until Escape or another tool |
| P | the Paint tool: one toolbar button for Brush, Line, Rectangle and Fill (its modes). It selects the last mode used (Brush at first); while a mode is the tool, a mode strip at the top left of the map (where the Note tool's options go) shows Brush, Line, Rectangle, Fill, and a click picks one; with a tiles layer active it also has **Random** and **Density** (see "Random and scatter brushes"). The active level's name tab steps aside from either strip: to its right while that is still over the level, else just under it. The mode is remembered across other tools and saved in `.worlds/ui.json` as `paint_mode`. Internally (gestures, `--tool`, scripts, undo labels) each mode is still its own tool |
| Single-key shortcuts | none of the keys below (tools, F, 1, +, -, PgUp/PgDn, Delete, arrows, Enter) fires while a text field has the keyboard: they are typed into it |
| V B R L G E T H | Select, Brush, Rectangle, Line, Fill, Eraser, Entity, Hand (B, L, R and G pick that Paint mode; on that mode already, nothing changes). T (also when the entity tool is already on) gives the palette's search box the keyboard and brings the Palette tab to the front; a non-entities active layer gives way to the first entities layer |
| Left drag (Brush, Eraser) | paint the palette value or tile stamp along the stroke; one stroke is one undo entry |
| Left drag (Rectangle, Line) | preview while dragging, apply on release; Shift makes the rectangle an outline |
| Click (Fill) | flood fill: int_grid values through `flood_fill`; on a tiles layer, the 4-connected cells with the same tile stack get the stamp as a pattern |
| Alt + click (painting tools) | pick the value or tile under the cursor into the palette |
| Drag in the atlas (tiles layer palette) | the tiles of the dragged rectangle are the brush: a stamp, or with Random on, one alternative per tile (Ctrl+drag adds those tiles to the alternatives, Shift+drag adds the rectangle as one stamp alternative) |
| Click or drag (Entity) | place the palette's brush where the button is released (a ghost follows the pointer); one entry, `add_entity` with a fresh id and the brush's field values. The type's `limit` is honoured in its scope (per layer, level or project) in the same entry: `prevent_adding` refuses with a status message, `discard_oldest` removes the oldest instances first, `move_last_one` moves the newest one here instead (`move_entity`; from another layer or level it is removed and added here with its id and fields). Validation still reports overruns made through commands or the API |
| Shift + drag (Entity) | size the box on the axes where the type is resizable, in project cells, from the start cell to the release cell (the other axes keep the type's size) |
| Ctrl + click (Entity) | pixel placement: the pivot point goes exactly under the pointer; `cell` is the cell holding the pointer, the rest goes in `offset_px` |
| Alt + click (Entity) | sample the type and field values of the entity under the pointer into the brush |
| Enter (Entity, keyboard on the map) | place the brush at the hovered cell, or in the middle of the active level when the pointer isn't over the map |
| Escape | close the topmost open prompt (unsaved changes, project changed on disk, delete level, new level), else the command palette, else cancel a canvas pick or the gesture in progress (a brush stroke is reverted, a drag of entities or a marquee is dropped). A prompt takes Escape before anything else sees it, so one press never does two things |
| Enter | confirm the delete-level prompt or the new-level dialog, but only when no text field or button has keyboard focus (Enter in a focused field belongs to the field) |
| Click (Select) | topmost first: a note card or dot, a pin's icon; an entity; a stack of the active layer when it is a visible, unlocked tiles layer; a path, guide or region outline within 4 screen px: select it (an entity's, a stack's or a level note's level becomes active). Locked annotations (guides) are selectable, to inspect or unlock, but never moved, nudged or deleted ("2 locked notes left alone"). An entity (on a visible, unlocked entities layer, in any level, which becomes active): select it; a click on an entity that is already part of a bigger selection narrows the selection to it; another level: make it active; empty space or outside every level: drop the selection |
| Ctrl + click (Select) | add the entity to the selection, or take it out if it was in it |
| Drag (Select) | from a selected item (or one the press just selected), or a selected level's body: move the whole selection by one delta, previewed from the very commands the release applies, one entry ("Move 3 items"; one kind: "Move 2 notes", "Move 2 levels", "Move 3 tile stacks"): entities by whole cells of their layer (Ctrl: pixels), tile stacks by whole cells of their layer (one `set_tiles` per layer, the moved stacks overwrite what is there, refused when a stack would leave its level), annotations by the delta snapped to the project grid (Ctrl: pixels; `update_note`), levels by it (`move_level`); things inside a moved level ride along. While levels move and Snap to guides is on (default; Notes pane, `ui.json`), their bounding edges snap to the x of vertical guide segments and guide vertices (y: horizontal ones) within 8 screen px, as built, visible guides only; the guide snapped to is highlighted. A level's own drag (its tab, or an unselected level's body, which it selects) snaps the same way. From empty space in the active level, whether or not the level is selected (as inside the level itself: its body is where you marquee, its tab is where you move it): a marquee picks the entities, the active tiles layer's stacks and the unlocked annotations it touches (that level's and world ones); the active level's tab moves the level, or the whole selection when the level is selected with other things; another selected level's body moves the selection. Every selection edit (drag, nudge, Ctrl+D, Delete) leaves selected entities on a locked layer alone and says so in the status bar ("Layer Objects is locked", or "2 selected entities are on locked layers: left alone" when others were edited).

Painting goes to the active layer. A locked or hidden layer, an auto layer and an entities layer refuse it with a message in the status bar (entities go down with the entity tool); cells outside the level are clipped. Tile brushes are stamps: a multi-tile palette selection is laid down whole, and a stroke repeats it edge to edge on the stamp's own lattice (starting where the stroke started). Tiles larger than the layer's cells sit on every `tile / cell`-th cell.

The Inspector shows the selected entities first (see "The Inspector" below), then the active level: slug and name (Rename), Delete, and the level fields, every type editable with the same editors as entity fields.

Saving writes only the files the edits touched (`worlds_core::save_dirty`), then re-runs validation for the problems panel (which also follows every edit; see "Live problems"). With `"export_on_save": true` in `project.json` it also writes `export/` from the editor's cached bakes. The title bar and the Save button show a dot while there are unsaved edits. Closing the window with unsaved edits asks Save / Discard / Cancel. When the project changes on disk: if every changed file holds exactly what our last save wrote there (or a level directory we deleted is still gone), it was our own save and nothing happens. That check hashes only the changed files and doesn't look at memory, so undoing right after a save doesn't prompt. Otherwise it reloads, or, with unsaved edits, asks first (Keep mine is the default).

The dock layout, camera, active level/layer, per-layer visibility/lock/opacity, tool, the Paint mode (`paint_mode`), palette brushes and the entity palette's state are saved per project in `.worlds/ui.json` (a layout saved before a pane existed gets it added: Rules next to the Log, Types next to the Inspector) (every 2 s when changed, and on exit). The editor watches the project directory (plus tileset image directories outside it). After 100 ms of quiet, a changed project JSON reloads the document, keeping view state that still applies, except when every changed file is an entity definition (`entities/*.json`) and none of them has unsaved edits: then each file is read with the core loader's checks and applied as `set_entity_def` (or `remove_entity_def { keep_instances: true }` for a deleted file) at the drain point (after an open stroke or agent batch ends), all of them as one undo entry labelled `Disk: entities/<slug>.json` (several: `Disk: N entity files`), origin user, reported as `changed`; the files are then marked clean (`Project::mark_clean`), since disk already holds them. Undoing that entry marks them dirty again, so the next save writes the old definitions back over the files. A queued file that an edit made dirty in the meantime (a panel edit or an agent request runs before the drain, or a stroke held the queue) isn't applied over that edit: the "changed on disk" prompt asks instead, as when it was dirty to begin with. A file that doesn't load (bad JSON, a slug that isn't its file name) keeps the old definition, with a status message, a toast and an entry in the Problems pane. Files whose content equals the open definition change nothing. A changed tileset PNG re-uploads just that texture and, if any auto layer's rules draw from it (the rules read tile opacity), drops those layers' cached bakes and rebakes every level on the workers; the old bakes stay on screen until the new ones arrive, and results from bakes started before the change are dropped. `.worlds/`, `export/`, `schema/` and `.git/` are ignored.

Annotations (`docs/format.md`: notes, pins, paths, regions, guides) are drawn on the map after the entity boxes (`src/viewport/notes.rs`), in the editor and in snapshots:

- **Cost**: every line, fill and icon of a frame goes into one mesh, guide segments culled by their box; text only from 12 px per cell and where free.

**The Notes pane** (`src/app/notes.rs`, a tab next to Problems; a layout saved before it existed gets it there): a search (title, body, id), kind, scope (All, World, This level, a level) and status (Open, Done, All) filters, tag chips (all of them must match); the rows (kind color, title or `<kind> <id>`, scope, tags, a Done box that is one `update_note`) built only when the project or the filter changes and drawn with `show_rows`; guides in a collapsed "Guides (n)" group at the end. ## The Rules pane

`Rules` is a tab next to the Log under the map (a layout saved in `.worlds/ui.json` before it existed gets it added there, or as a split under the map when there is no Log). It comes to the front whenever the active layer becomes an `auto` layer, and from the Palette's "Open in Rules" (the Palette of an auto layer lists its groups and rules in run order under the same `Pass n` headers as the pane; a click selects one in the pane). It edits one auto layer at a time (the combo top left; default the active layer) and shows counts for the active level. Every edit below is one command batch, so one undo entry with a label like "Rule r_146: pattern", and goes through the same path as any edit (`Editing::after`; an agent gets the user's `changed` event).

Left, the list, in evaluation order:

| Row | Shows | Edits (command) |
| --- | --- | --- |

**Renaming** a group, a rule or a reference: the slug turns into a box with the text selected; Enter or leaving the box renames, Escape cancels. A slug that isn't one, or that another group (for a group) or another entry or expanded rule `<reference>__<rule>` (for an entry) of the layer has, is refused: the reason shows under the box and in the status bar, and the box stays open to fix it. The pane's selection, collapsed groups and opened references follow the new slug. A rule's slug seeds its random choices, so a renamed rule with `chance`, alternatives or perlin re-rolls (set `salt` to taste).

Below the list, the template library (`rules/macros.json` templates and the built-ins, with their `doc`): Apply… opens a dialog with the reference slug, tileset, origin (type it, or click the atlas: the template's tiles at that origin are outlined and numbered by template rule, so you see where each piece lands), target group and index, and sends `set_rule` with a `use` entry. Built-ins also have "Copy into macros.json" (`set_macro`). With "Replace by a reference" the same batch removes the rules and puts a reference where they were; that needs the rules to be one run of one group (rules of two groups, or with an unselected rule between them, would change priority or group conditions) and a reference slug no other entry has, and the dialog says so otherwise. Right, the selected entry:

- **Pattern**: the grid it reads (combo; the layer's `source` is left implicit), then the pattern as a grid of colored cells (value colors; `*` dark, `.` black, `+` light, negated tests dimmed and struck through, the anchor outlined in the accent; hover says what a glyph means). Click a cell to cycle its glyph through `*`, the grid's value and group glyphs, `.`, `+` and the pattern's own legend glyphs; right click sets `*`; Alt+click puts the anchor `@` there (an existing `@` becomes `*`); Shift+click paints the glyph chosen among the chips below the grid. `+ ring` / `− ring` grow or shrink around the center, `+ row` / `− row` / `+ col` / `− col` work at the bottom and right edge. Each click or button is one `set_rule`. Named rows (`rows = edge_top`) show resolved and read only, with "Make inline".
- **Text**: the same pattern as you'd write it: the rows, a blank line, then `glyph = test` lines (`rows = name`, `legend = name` for names in `rules/macros.json`). Enter commits (`set_rule`), Shift+Enter is a new line, leaving the box commits too. A line that doesn't parse is reported under the box and nothing is sent; a pattern that parses but has problems validation will list (a glyph meaning nothing on the grid, an even size without `@`, two `@`) is sent, with a warning shown.
- **require** (collapsed): the same grid and text for the second pattern, Add / Remove.
- **Options**: mirror x, mirror y, rotate; break; chance (a slider, committed on release); modulo (x, y, offsets) and checker; perlin (active, seed, scale, octaves); out_of_bounds (no match, `.`, or a value); salt with Re-roll. Numbers commit when a drag ends or the field loses focus.
- **Output**: tileset, mode (stack / stamp, with pivot), the alternatives (tiles, weight, remove), alpha and offsets (fixed, random), and the atlas (the palette's texture cache, `tile_at_px` hit-testing) with every alternative's tiles outlined and numbered: a click makes that tile the only alternative, Shift+click or a dragged rectangle adds one. Stamp outputs pick the stamp.
- **A reference**: template, tileset, origin (or click the atlas, where its pieces are outlined), legend overrides (`# = fortified, S = !fortified`, committed on Enter), its tile overrides with "clear", Detach, Delete.
- **An expanded rule** (`walls__fill`): read only (it lives in the template), but its atlas edits the reference's `tiles` override for that rule, relative to the reference's origin.

**Highlight.** For the selected rule, reference or expanded rule, in the active level, the canvas fills the cells where it fired (from the level's current bake, `LayerBake::fired`) with the accent and outlines in orange the cells where its pattern matches but it didn't fire (chance, perlin, or an earlier rule's break): `worlds_rules::rule_matches_many` minus fired. Matches are worked out for every entry of the layer at once (about 2.5 ms for a 32-rule layer on a typical level, release) and cached by (edit revision, level, layer); they aren't redone during a gesture, so a stroke doesn't pay for them per move. The counts in the rows, the group headers and the pane header come from the same data, which is what `rules.preview { matches: true }` reports to an agent. Hovering a cell of an auto layer lists the rules that fired there in the status bar (`BakeCache::placements_at`, else the bake's `fired`).

## Derived layers, passes and region rules

A **derived** int_grid layer (`"derived": true`) holds what an auto layer's `write` rules compute, plus hand-painted overrides (`docs/format.md`).

- **Layers pane**: a `derived` badge where the kind goes, its tooltip naming the writer ("computed by pillars's rules; painting sets overrides").
- **Map** (the window, `--snapshot` and `view.snapshot` alike, `scene::derived_cell`): the layer draws its **effective** grid: a computed cell in the value's color at 45 % of the layer's opacity, an override at full opacity with a 1 px darker outline, a suppressed cell (`!`) a small grey ×. The computed values are the writer's current bake (`LayerBake::derived`, so they follow every rebake: an auto layer's invalidation also dirties the derived layers' chunks), the overrides the level's stored plane. The status bar names the state under the pointer: `pillar_marks: pillar_base (rules)`, `(override)`, `suppressed (rules: pillar_base)`, `empty (rules)`.
- **Palette and tools**: the layer's values plus **Suppress (!)**. Brush, Rectangle and Line paint overrides (`paint_cells` / `fill_rect` with the value, or `"!"`); the Eraser (and the Erase brush) removes overrides (`null`: back to the rules). **Fill floods the effective region**: the 4-connected cells with the same effective value as the clicked one (what the map shows, overrides over computed), sent as one `paint_cells` with the brush, never `flood_fill` (which works on the stored plane). Alt+click picks the stored state: an override's value, Suppress, or Erase where the rules decide. Each gesture is one entry and saves only that level's `<layer>.json` (which goes away with the last override).
- **Export on save** writes each derived layer's effective grid (`Document::derived_effective`: the stored overrides over the writer's current bake, the bake the cache keeps current), so `export/` is byte for byte what `worlds_rules::bake_for_export` (`worlds-cli bake`) writes.

**Bakes in dependency order.** The whole-level worker bakes (at open, after a tileset image change) run `BakeCache::bake_detached`: every auto layer of the level, writers of derived grids before their readers, each succeeding or failing on its own. A level whose every layer is stored as baked keeps the result (`LevelSeed`), and the first edit there hands it to the command layer's cache whole (`BakeCache::seed_level`: pass state, occupancy and effective grids included, no bake on the UI thread); otherwise the cache is seeded layer by layer in dependency order. A rule edit on a writer also rebakes the layers reading its grids (transitively), in the active level at once and on the layer workers elsewhere. With a region-rule pass and an occupancy pass, a brush step on a level's collision (regions recomputed, the occupancy pass re-swept whole) costs 0.16 to 0.38 ms applied and rebaked (release, Intel UHD 630); `--synthetic 500 --bench 300` with those layers: 500 levels baked in 232 ms on one thread (headless), `ui_ms` p50 / p95 / max 1.18 / 1.77 / 1.93, `total_ms` 5.35 / 6.59 / 6.78 (1600x900, world framed).

**Rules pane.** The list is in run order under `Pass 0`, `Pass 1`, … headers (groups sorted by `pass`, stably), with an empty `Pass n+1: drag a group here to start it` at the end. A group dropped on a `Pass n` header goes first in that pass, and one dropped on another group's header takes that group's pass and place: one `set_rule_group` (pass and index), one entry. A rule dropped on a pass header goes first in its first group (`move_rule`; rules move between groups of any pass as before). The group header's second line edits `pass` (a number, committed on release; when the file would leave pass order the group also moves to the nearest place that keeps it) and `requires_level_tag` (a popup: any / all, tags comma separated, empty for none), each one `set_rule_group`. `+ Region` adds a region rule. A region rule's row reads `region . w≥15 · floor every 6`, a write rule's `writes pillar_marks ■ pillar_base`. The editor of a region rule: **Region** (grid, the source by default, derived layers marked; `cells` as text, Enter commits; min and max width, height and area: an unset bound shows `none`, and dragging it to 0, typing 0 or clearing it unsets it, since a bound is at least 1), **Place** (along floor / ceiling / wall_left / wall_right or across interior; spacing even / spread / random; every and margin, `[x, y]` across; align for even, jitter for random, min_length and against for along; switching keeps the file valid, e.g. `[x, y]` collapses when switching to along), **Options** (break, salt with Re-roll) and **Output**: Draw (tiles or a stamp, as before; `avoid overlap` on both) or Write (a derived layer on this grid and one of its values). Every edit is one `set_rule`. **Highlight** of a selected region rule, besides its firings (filled) and candidates that didn't fire (an orange ring between a dark outer and a light inner ring, so it reads on any cell colour, an orange derived value included): with **Show regions** (on by default) each region's bbox outlined with a `w × h` label, the selected ones in the accent and the rest dim grey, and the runs of its edge as 2 px lines along that edge (`worlds_rules::region_preview`, one bake of the layer, recomputed only when the edit revision, the images, the level, the layer or the rule changed and no gesture is running). **Show occupancy** hatches the cells the layer's stamps occupy in the active level (`LayerBake::occupied`); a placement skipped by `avoid_overlap` is one of the orange "matched but didn't fire" cells.

## Random and scatter brushes

On a tiles layer the brush can be a list of weighted alternatives instead of one stamp (`tools::Brush::Random`), in the same forms as a rule's `out.tiles` (`worlds_core::TileAlt`): `[col, row]`, `[col, row, w, h]`, `{ "rect": [col, row, w, h], "weight": n }`, `{ "stack": [[col, row], ...], "weight": n }`, all from one tileset. Each painted cell (each cell of the tile lattice when tiles are bigger than the layer's cells, as for stamps) picks one alternative by weight: tiles that form a rectangle listed row by row keep their atlas layout with the top-left tile on the cell (one tile, or a stamp), any other `stack` is drawn on the cell in list order. A pick whose tiles would land on a cell the same gesture already filled is skipped, so stamps never cut into each other and scrubbing back over a stroke changes nothing. Brush, Line, Rectangle (and its outline) and Fill all paint with it; Rectangle and Fill keep only the tiles inside their area. Weight 0 is never picked; a brush with nothing to pick is refused with a message.

- **Paint strip**, with a tiles layer active: **Random** turns the current stamp into a random brush of its tiles (one alternative each, weight 1) and back (the first alternative's rectangle). **Density** (1 to 100 %, default 100) skips cells: each lattice cell of a stroke, rectangle or fill is painted with that chance, with any tiles brush (a stamp brush skips whole stamps on a stroke, single tiles in a rectangle or fill). Int_grid layers ignore it.
- **The palette** with a random brush: a drag in the atlas replaces the alternatives with the dragged tiles, Ctrl+drag adds them, Shift+drag adds the rectangle as one stamp alternative; every alternative is outlined in the atlas. Above the atlas the alternatives are listed with their weights (drag to change, `×` drops one) and **Save preset** stores the brush under the typed name (the same name replaces it). Saved presets are listed under it on every tiles layer: a click makes one the brush (and shows its tileset), a right click forgets it.
- **Randomness is the brush's, not the project's**: each gesture draws a fresh seed (`tools::fresh_seed`), and a cell's roll is `tools::cell_roll(seed, cell, salt)` (density, then pick), so one gesture is consistent with itself, and what lands is what is saved. A script brush's `seed` fixes it for tests.
- `.worlds/ui.json` keeps the density and the presets in `palette` (`density`, `presets: [{ name, tileset, alternatives }]`, both optional, so older files load with 100 % and none); the brushes themselves, random ones included, are saved per layer as before.

## The entity palette and the canvas

On an entities layer the Palette tab is the entity palette (`src/app/entities.rs`), four stacked parts, each collapsible by its header:

1. **Search** (top). Fuzzy over name, slug, category and tags (`actions::fuzzy_score`), ranked name > slug > category > tag. Typing filters every part below. It gets the keyboard when the entity tool is entered and on T; Escape clears the text (keeping the keyboard), a second Escape gives the keyboard back to the map. Enter picks the first hit as the brush and gives the keyboard back, so a second Enter places it; with no hit it says so in the status bar and the search box keeps the keyboard, to fix the query. Under the box: the tag chips (`+ tag`; each chip filters the catalogue, all of them together), the grid / list toggle, and the brush.
2. **Favorites** (★ on any row, or right click), then **Recent**: the last eight types placed in the project, most recent first.
3. **In this level**: every type in the active level with its count; the `×N` button selects all of them (the Inspector shows the fields they have in common).
4. **Catalogue**: a tree by `category` (`Puzzle/Doors`; `Uncategorized` last), each category collapsible with its type count; icons in a grid, or rows. With a search it is the matches instead, best first.

A click on a type makes it the brush (a new type starts with no field values) and switches to the entity tool. The brush's field values (from Alt-click or a script's `fields`) are only keys its type defines, and they follow the type: a field renamed, retyped or removed drops its value, so placing never writes a stale key. Hover shows the type's name, slug, category, tags, `doc`, size, limit and fields. Right click: Favorite / Unfavorite, Edit type… (opens it in the Types pane) and Duplicate type (a `set_entity_def` of a copy under `<slug>_copy`, named "<name> copy", one entry, then opened in the Types pane). Icons come from the tileset atlas textures the Palette and Rules pane share (`icon.tile` with the tileset's `tile_size`, `spacing` and `padding`), a square of the type's color without one.

Favorites, recent, collapsed parts, chips, the view and the brush's type are saved in `.worlds/ui.json` as `entity_palette` (every key optional, so older files load; types the project doesn't have are dropped on restore). The rows are one flat list rebuilt only when what they show changes (definitions via `defs_gen`, query, chips, collapsed parts, view, favorites, recent, the level's counts, the grid's width) and drawn with `ScrollArea::show_rows`, so a frame pays for the visible rows only; the level's counts are cached per (edit revision, level). A reload forgets all of it (the new document's counters start over), and `defs_gen` carries on from the old document. A query that only appends characters scores just the last query's hits (a subsequence match of the longer query is one of the shorter), and hits are ordered by a name order cached per `defs_gen` instead of comparing lowercased names in the sort. Search hits are real: for "door", every hit among the synthetic types has "door" in its name, slug, category (`.../Doors/...`) or a tag (a test checks it). `--bench 300 --bench-palette door` at 1600x900 on the Intel GPU (release; the search grows a character per frame and starts over every fourth):

| Types | `ui_ms` p50 / p95 / max | `total_ms` p50 / p95 / max |
| --- | --- | --- |
| 100 | 1.4 / 2.0 / 3.5 | 5.2 / 6.4 / 10.6 |
| 1000 | 2.0 / 2.4 / 7.0 | 6.1 / 6.7 / 14.2 |

**On the canvas** an entity is its box (fill and outline in its type's color; `worlds_core`'s `EntityDef::pixel_rect`, the one source of truth for drawing, hit-testing, the marquee, the ghost and snapshots: position `(cell + pivot) * layer grid + offset_px`, size in project cells times the project grid, whatever the layer's grid) with its icon inside. A box smaller than 6 screen px is just its fill (no icon, outline or labels; selected ones keep the accent outline). Selected entities are outlined in the accent. From 24 screen px per cell the type's slug sits above the box and up to four `display.canvas` fields below it as `slug: value`; from 12 px, the `display.world` fields' values under it; below 12 px no labels (on the flat zoomed-out levels, the `display.world` values again, by a dot). Labels are drawn after every box, so no box covers one, the selected entities' first; a label that would overlap one already drawn is skipped, so a crowded map stays readable and its text costs what the screen holds. `display.arrow` fields draw arrows from 8 screen px per cell (a selected entity's at any zoom): an `entity_ref` to its target's box (in any level), a `point` to its cell, in the type's color (the accent for selected entities). A layer's fills and outlines are one mesh and its icons one mesh per atlas, so a zoomed-out map of a thousand entities costs a few shapes, not thousands. With the entity tool, a ghost of the box the release would place follows the pointer (with its size while Shift-dragging).

## The Inspector

The Inspector (`src/app/inspector.rs`) shows the selection first, then the active level. Every edit below is one command batch, so one undo entry with a label like "Set channel on 2 entities", through the same path as any edit.

- **One entity**: its type's icon and name, the type's `doc` (in italics) right under it, then Id, level and layer, and **Cell**, **Offset px** and **Size** as editable numbers (`move_entity`; an offset of a cell or more folds into the cell; `resize_entity` on the axes the type can resize, `×` goes back to the type's size). Then every field of the type, with the editors below; what validation says about a value (live problems: over its `max`, failing its `regex`, not an enum value, an array element's `[i]`) is shown in red under it. Stored keys the type has no field for are listed in red with `×` to remove them (undo puts them back). Duplicate (Ctrl+D), Delete and Deselect sit on top.
- **Several entities**: "N entities" (or the type and "N selected"), then the fields every selected type has: same slug, type, array-ness and enum source (bounds may differ). A field whose value differs between them shows "—"; an edit sets it on all of them as one batch of `set_entity_field` ("Set direction on 2 entities"; `×` clears it where it is stored). When the selection spans levels, point fields can't be picked on the map (a cell is of one level).
- **The level**: slug and name (Rename), Delete level…, **Resize** and the level fields, with the same editors and the same problem notes. Resize has a 3x3 anchor picker as in image editors' canvas size dialogs (the dot is what stays put in the world, arrows point where the level grows; default the center, as for `resize_level`), the new width and height in project cells, **Resize** (one `resize_level` with that anchor, refused with a message when an entity would end up outside) and **Crop to content** (`Project::crop_level`: shrink to the bounding box of the non-empty cells, tiles and entities, one undo entry "Crop level <slug>"; the command palette's "Crop level to content" and the level's right-click menu do the same).

The field editors (`src/app/fields.rs`, shared by the Inspector, the multi-select and the Types pane's defaults) commit once per edit, never per keystroke or per frame of a drag:

| Type | Editor |
| --- | --- |
| int, float, string, path | a text box, committed on Enter or focus loss; a value that doesn't parse is shown under it in red and nothing is sent; path shows its allowed extensions |
| text, json | a multiline box, committed on Ctrl+Enter or focus loss; json is parsed then (the error shows inline) |
| bool | a checkbox (indeterminate when mixed) |
| color | the color button; committed when the picker closes |
| enum | a combo of the values with the project enum value's icon or color |
| point | x and y (a value that doesn't parse is noted under that axis), and **Pick**: the next click on the map sets the cell (in the field's level and grid: the entity's layer, the project grid for level fields); Escape cancels |
| entity_ref | the id, and **Pick**: the next click on an entity in any level, the world view too; `type @ level` on its own line under it (wrapped, never cut), "missing" in red when no entity has that id |
| tile | its icon, the tileset (fixed when the field names one) and an atlas popup to click the tile in |
| arrays | a row per element: its index and editor, then ⏶ ⏷ × (move up, move down, remove) at the row's right end; then a line with + (for points and references, "+ Pick" adds what the next click picks) and the field's own `null` and `×`, so nothing runs past a narrow Inspector; every change sends the whole array as one `set_entity_field` |

`null` stores null (nullable fields); `×` removes the stored value so the default applies (the row says "default" when nothing is stored). A Pick arms a canvas pick (`view::PickRequest { accept: { entity, cell }, target, prompt }`, generic so later kinds can pick levels or notes): the next left click on the map goes to it instead of the tool, the status bar says what to click, Escape (or the Pick button again) cancels, and the answer (`view::Picked`) goes to the editor that asked.

## The Types pane

`Types` is a tab next to the Inspector (`Pane::EntityDefs`, `src/app/defs.rs`; a layout saved before it existed gets it there, else next to the Problems, else as a split right of the map). It opens from the palette's right click (Edit type…, Duplicate type), from a problem that names a type or the level fields, from the command palette ("Edit level fields") and from a `"ui": "types"` step.

- **List**: a filter and New type (`new_type`, one `set_entity_def`) at the top of the pane (they stay when it scrolls), then "Level fields" and every entity type (name and slug); a type opened from elsewhere is scrolled into view in the list.
- **A type**: its icon, name and instance count; Duplicate (a copy under `<slug>_copy`), Delete… (asks first, saying how many instances go with it; `remove_entity_def`; undo brings them back). Its form, folded under "Type": slug (Enter renames: `rename_entity_type`, instances and `allowed_types` follow), name, category, tags (comma separated), doc, size, resizable, pivot (numbers or presets), icon (tileset and an atlas popup; `×` for none), color, limit (on/off, max, scope, behavior). Each change is one `set_entity_def` labelled "Edit type door: size".
- **Fields** of the type or the level fields: one row each, `☰` to drag it onto another row (above or below its middle: `set_entity_field_def` / `set_level_field_def` with `index`), Dup (a copy under a new slug right after it), `×` (asks first and says how many entities, or levels, store a value that goes with it; undo brings them back; `remove_*_field_def`), + Field. Clicking a row opens its form: slug (Enter renames: `rename_*_field`, stored values follow), name, doc, type, array, nullable (a type or array change drops the default, stored values stay for validation to report), default (the Inspector's editors), the type's options (min and max; regex; values from a project enum or inline values; allowed types and tags, cross level; extensions; tileset) and display (canvas, arrow, world). Each change is one `set_*_field_def`.

A command the pane sends that the command layer refuses (a rename onto a slug the type already has, or that an instance already stores a value under) comes back to the pane and is shown in red under the list. A rename moves the form to the new slug only once it applied, so a refused one leaves the form where it was. Edits committed in the same frame (a name typed, then a checkbox clicked) build on each other, renames included, so none is lost.

## The Project pane

`Project` is a tab next to Types (`Pane::Project`, `src/app/project_pane.rs`; a layout saved before it existed gets it there, else next to the Inspector, else as a split right of the map). It is what a fresh project (`worlds-cli new`) needs before anything can be painted, so nobody has to write `layers.json` or `tilesets.json` by hand. Three parts, picked at the top (`Layers (n)`, `Tilesets (n)`, `Settings`), each naming the file it saves. It opens from the Layers pane (an empty one has **+ Add a layer…**; a double click or right click on a layer, Edit layer…; **Edit layers…** under the list), from the Palette (a tiles layer with no tileset: **+ Add a tileset…**; an int_grid layer with no value: **Add values…**), from the command palette ("Project: layers", "Project: tilesets", "Project: settings") and from a `"ui": "project"` step.

- **Layers**: **+ Layer** (Int grid, Tiles, Auto, Entities, each with what it is for) adds one on top, makes it the active layer and opens its form: an int_grid layer is `collision` (the first one; then `grid`) with one value `solid` (`#`), an auto layer is `walls` reading the topmost int_grid layer (offered only when there is one), a tiles layer `decor` on the first tileset, an entities layer `objects`. The list is top layer first (as in the Layers pane), with the kind, `⏶` `⏷` (`set_layer_def` with `index`) and `×` (asks first, saying in how many levels it has content; `remove_layer_def`, undo brings it all back). The form: slug (Enter renames: `rename_layer`, level files, rules and the collision setting follow), name, kind (refused by the command layer while the layer has content: the message shows in red), doc, opacity (committed on release), grid (empty: the project's). An int_grid layer adds **Derived**, its **Values** (color, glyph, slug, name, group when it has groups; `⏶` `⏷` `×`; **+ Value** with a fresh slug, the next free glyph and color) and **Groups** (color, glyph, slug, name, `×`, which ungroups its values; **+ Group**; a renamed group's values follow). An auto layer: source (the int_grid layers), tile pivot, and its rule count with **Open in Rules**. A tiles layer: its default tileset. An entities layer: **Open Types**.
- **Tilesets**: **+ Tileset…** opens the native file dialog (`rfd`, on its own thread) for a PNG. One inside the project is used where it is; one outside is copied into `art/` first (an identical file there is reused, a different one of the same name becomes `name_2.png`), and the pane says so. The tileset's slug comes from the file name, its tile size is the project grid. The list shows each one's image and tile size, `×` (`remove_tileset_def`: refused while anything uses it, with the uses listed). The form: slug (Enter renames: `rename_tileset`), image (typed, or Browse…), tile size, spacing, padding, and the image at its own size (twice that when small), scrolled, with every tile outlined as the editor cuts it, its size and tile count above (hover: the tile's `[col, row]`). A path that doesn't load says so in red.
- **Settings**: name, grid (only while there are no levels: `set_project_setting` `grid_size` is refused once there are; "match your art's tile size"), background (default, or a color; `×` back to the default), collision layer (none or an int_grid layer; choosing one also sets its blocking values to its `solid` value, as loading would), its **blocking values** as checkboxes (`blocking_values`), seed, **new level size** (`default_level_size`, typed as `40x22`; empty or `×` leaves it out, and New Level then uses the most common size, shown greyed), **export on save** (`export_on_save`).

Every edit is one command batch, so one undo entry ("Edit layer collision: add value", "New tileset tiles", "Collision layer: collision"), through the same path as any edit (undo, the live API's `changed` event, autosave). The pane's commands go through `ProjectState::pending` like the Types pane's: a refusal (a kind change of a layer with content, a value cells still hold, a tileset in use, a slug taken) is shown in red at the top of the pane, and a rename or a new layer or tileset is followed only once it applied. Edits committed in one frame build on each other.

## Live problems

The Problems pane follows every edit (`src/app/problems.rs`). Any edit, undo, redo or agent write bumps the command layer's revision; once the project has been quiet for 200 ms and no gesture or agent batch is open, the editor revalidates, so a stroke is one revalidation after it ends, never one per move. `worlds_core::validate` takes about 0.15 ms on a 5-level project but 28 ms (p95 30 ms) on `--synthetic 500 --synthetic-entities 100` (release), over the 4 ms a frame can spare, so the window validates on a worker thread against a clone of the project (about 2.4 ms for that world) tagged with the revision; a result for an older revision is dropped. Headless renders validate inline, with no wait, so the picture is complete. `problems` goes to the live API only when the list changed. Entity files that didn't load from disk stay listed until they load.

Clicking a problem that names an entity (`...entities[<id>]...`) selects it and frames its level; one in `entities/<slug>.json` opens that type in the Types pane, one in `project.json`'s `level_fields` the level fields; one in a level's directory frames that level.

## Autosave and crash recovery

DESIGN: "Autosave writes to `.worlds/autosave/` every 30 s and on crash recovery offers the diff." The files are in [`worlds_core::autosave`](../worlds-core/src/autosave.rs) (format in [`docs/format.md`](../../docs/format.md)); the editor side is [`src/autosave.rs`](src/autosave.rs) (when, and the writer thread) and [`src/app/recovery.rs`](src/app/recovery.rs) (the lock message, the prompt, `--recover`).

**Session lock.** An editing session (the window always; headless as above) takes `.worlds/editor.lock` with `File::try_lock` when it opens the project and holds it for the document's life; the OS releases it when the process dies, however it dies. The file is never renamed or deleted (a new inode at that path would be a second, free lock); who holds it (`pid`, `started`, `version`) is in `.worlds/editor.json`, written atomically, for messages only. A second editor on the project: the window shows "Project already open" with Quit (and opens nothing), headless exits 2. Where the filesystem can't lock, the session goes on without autosave or recovery (a toast says so; two editors would otherwise overwrite each other's autosave). A folder without `project.json` isn't opened, and nothing is created in it. **Opening another project** (File > Open) with unsaved edits asks first (Save / Discard / Cancel; Discard drops the edits with their autosave). The open project's unsaved edits are autosaved before it goes (they are offered back when it opens again), and its lock is released only after the autosave writer is done; a write still running after 5 s refuses the switch ("try again") and keeps the lock. Re-opening the same project waits for the writer too, so it never mistakes this session's own autosave for a crashed one. Closing waits up to 5 s as well; a write still running then keeps the lock until the process exits. A `--synthetic` world takes no lock and never autosaves.

**Autosave.** What is written is exactly what Ctrl+S would write now: `worlds_core::format::render_dirty`, the function `save_dirty` itself writes from (the dirty files' bytes, and the files the save would delete), into `.worlds/autosave/g<N>/`, then `manifest.json` atomically (the commit point: generation, time, pid, rev, the newest undo label, the dirty set verbatim, and per file `modified`/`deleted` with the `base` hash of the disk file as loaded or last saved and the `hash` of the bytes), then the older generation is removed. A kill at any moment leaves the old manifest with its generation or the new ones, never a torn one. It fires 30 s (`--autosave`, `WORLDS_AUTOSAVE_SECS`) after the first edit since the last autosave, at once when the window loses focus, and on SIGINT/SIGTERM; never inside a gesture or an agent batch (it waits for the end, at most 60 s); only when the document is dirty and its revision changed. Rendering happens on the UI thread (a 5-level project, one stroke: 0.02 ms; 50 dirty levels of a 500-level world: 1.2 ms p95, release); the writing on the `worlds-autosave` thread, one write at a time, a newer request replacing a queued one. A save (Ctrl+S, the close prompt's Save, `project.save`, `--save`), a reload, and the close prompt's Discard remove it; a clean exit removes it, an exit with unsaved edits (a signal) keeps it. A revision counts as autosaved only once its write succeeded (the writer reports each finished write back): a failed write is a toast and is written again one interval later (or at the next focus loss), and the signal path writes again when the newest autosave failed. If the writer thread can't be started, writes run on the UI thread instead. `.worlds/` is ignored by the watcher.

**Recovery.** On open, with the lock taken, an autosave left behind is a session that ended without saving. It is validated (every file present and matching its hash; otherwise it is moved to `.worlds/autosave.discarded/` with a toast) and compared with the disk (a project file that can't be read, e.g. permissions, leaves the autosave alone, as Later, with a toast; it isn't taken for a broken one): files already on disk drop out (a kill between a save and the autosave's removal leaves nothing to ask), and a file whose disk bytes no longer match its `base` (git, an agent's headless edit) is a **conflict**. What is left is offered in the "Recover unsaved edits?" prompt (screenshot `recovery_prompt.png`): the session's pid, time and last edit, the counts (`+48 −116 lines`), and one row per file with its state, `+/−` lines and a conflict badge; a row opens to the unified diff, disk to autosave (scrollable; the first modified file is open). Buttons:

- **Recover**: load the disk with the autosave on top (`worlds_core::format::load_with_overlay`): the files are in the document *unsaved* (the dirty set is the crashed session's, so Ctrl+S writes and deletes exactly what that session's save would have; the known files come from the disk, so a deleted level or entity type is deleted). Undo history starts empty. Conflicting files are skipped (the disk wins) unless "Recover conflicting files too" is ticked; skipped ones aren't lost: the old autosave moves to `.worlds/autosave.discarded/` first. Recover refuses while the open document has edits made since the prompt came up (they would be replaced). Recover looks at the disk again first: if anything changed while the prompt was up (a file is a conflict now, or already saved), the prompt shows the new state with a note instead of applying the old decisions, and a file that changes during the load itself refuses the recovery. The status bar says "Recovered N files from autosave; Ctrl+S to keep them", and the live API's `project.describe` gains `recovered: { files, skipped, session: { pid, written } }`.
- **Discard**: move the autosave to `.worlds/autosave.discarded/` (the one discarded before is replaced) and keep the disk.
- **Later**: keep it for the next start. This session isn't autosaved meanwhile (it would overwrite it); the status bar shows "Autosave off: last session's edits waiting" (click to decide), and the first save asks again.

Headless tools tell a live editor's autosave from a crashed one by the lock (`worlds_core::autosave::pending`): `worlds-mcp` in headless mode adds `autosave` to `describe_project` and a notice, `worlds-cli bake` prints a warning; a live editor's autosave is not mentioned.

## Live API

The editor hosts [`worlds-server`](../worlds-server/README.md) (JSON-RPC over a localhost WebSocket, [`docs/api.md`](../../docs/api.md)) for the open project: the window always, `--screenshot` with `--serve`. Opening a project starts it (`Server::start`, the wake callback is `ctx.request_repaint`, so a request wakes an idle editor); opening another project stops it and starts a new one; closing the editor stops it and removes `.worlds/server.json`. SIGINT and SIGTERM (`kill`, `xvfb-run` teardown, Ctrl+C in the terminal) do the same: the window closes without the unsaved-edits prompt, but first autosaves unsaved edits synchronously (rendered on the UI thread, then waiting at most 5 s for the writer, well inside the 10 s grace), so the next start offers them back (see "Autosave and crash recovery"); the server stops and the file goes; `--serve` treats them like the end of its wait (autosaving the same way when autosave is on) (`src/signals.rs`; if the shutdown takes over 10 s the process exits anyway). The window exits with status 0 after a signal, like any close: once `eframe::run_native` returns (the app's `on_exit` has stopped the server, removed `server.json` and written `ui.json`), `main` ends the process with `signals::exit_now`, which flushes stdout and stderr and calls `_exit`. That skips libc's exit handlers on purpose: eframe keeps winit's event loop in a thread-local, and dropping it there segfaulted under Xvfb in winit's X11 keymap teardown (`XkbKeymap::drop`, in libxkbcommon), after all of our state was safe. `window_exits_cleanly_on_signals_under_xvfb` (below) checks it. A kill that can't be caught (SIGKILL, a crash) leaves a stale `server.json` behind; clients ignore it because its pid is gone, and the next editor overwrites it. When another live process already serves the project (`AlreadyRunning`), the editor runs without a server and the indicator says why.

**The drain point.** `EditorApp::frame` drains the queues once per frame, after the frame's tool events and queued panel commands have gone to the command layer (`app/agent.rs`, `live_frame`). It skips the drain while a gesture is in progress (the viewport's drag or the command layer's open stroke), so a request during a stroke waits until the stroke ends, reads too. The document is lent through `live::EditorHost` (the `Host` impl): `doc()` hands out the project, the `Editing` history and bake cache, the tileset images; `applied()` is `Editing::after`, the path every user edit takes (chunk invalidations, incremental rebake, re-index on level create, delete and rename), so an agent edit is on the canvas the next frame; `save` is the editor's save (dirty files, `export_on_save`, problems, own-write bookkeeping so the file watcher doesn't prompt); `reload` re-reads the project and the app finishes it after the drain (scene, bakes, watcher); `problems` refreshes the panel; `focus` makes a level active and frames it, or frames a world rect; `select` maps `{ level }` (make it active, clear the selection) or the lists `{ entities, notes, levels }` onto the selection (`view::SelItem::{Entity, Note, Level}`, in that order, the first primary; the active level becomes the first entity's, else the first level note's, else the first listed level's; unknown ids are refused before anything changes); `focus { note }` frames the annotation's box as built, grown by 15 % and to at least 8 project cells, and makes a level note's level active. The `selection` event reports `level` (the active level), `entities`, `notes` and `levels` (slugs); selected tile stacks have no id and aren't reported.

**Ordering.** Before the user records an entry (a gesture's `Begin`, an inspector or menu command) or steps undo or redo, the app calls `flush_batches`, so an agent's open batch is recorded up to that point first. Each entry the user records and each undo or redo step is reported with `notify_changed` (origin user, label, changes; `Editing::take_user_edits`); a user save sends `saved` and `problems`; `problems` is also sent whenever the live list changes (see "Live problems"); a user reload sends `notify_reloaded`; a changed active level or selection sends `selection`.

**Toasts and the indicator.** Toasts stack upward from just above the status bar, newest at the bottom. Each is one line of a fixed height (long text is cut; hover shows all of it, and every toast is also in the log), so the stack is laid out from the style alone, never from a size measured the frame before, and never reaches the status bar or the toolbar. At most four are drawn (fewer in a short window); older live ones fold into a "+N more" line on top, and at most 32 are kept. Every new agent entry gets a toast with an Undo button. It undoes exactly that entry, and only while it is the top of the undo stack (same depth and the same entry); otherwise the button is disabled and says why. The toolbar's right end shows the connection (green dot, the client's name or count, names and versions on hover, the port), the last agent batch's label, the pending count and the **Approve** toggle. It gets the room the tools leave, and in a narrow window it collapses rather than overlap them: the label is cut, then dropped, then the client's name, then the pending count shrinks to a number; the dot (whose tooltip has all of it) and Approve always stay. Approval mode is off at start, per session, never saved in `ui.json`.

**Approval mode.** With Approve on, agent writes become pending batches. Each is drawn on the canvas as a ghost (`src/ghost.rs`): the batch is applied to a scratch clone of the project and the cells its changes name are drawn in their new value's color at 50% alpha (tiles cells in a blue tint, emptied cells dark), with a dashed outline of every changed rect; entities as dashed boxes (removed ones red); touched levels as dashed outlines. A batch that no longer applies to the current project is drawn as outlines only and marked stale. The "Agent batches waiting" panel sits in the Map pane's top-right corner (kept inside the map, so it never covers the inspector) and lists them oldest first with Apply (`apply_pending`, through the same `applied()` path; one agent entry, a toast; only on the oldest batch, since later ones may build on it, and the server refuses them out of order too) and Reject (`reject_pending`, which also rejects that client's later batches; the project and `rev` don't change). Clicking the ghost itself does nothing yet: use the panel.

**Snapshots.** `view.snapshot` renders with `snapshot::SnapshotRenderer`, which owns its own offscreen wgpu device (`headless::Headless`), egui context and a `Viewport` in map-only mode. It is created on the first snapshot and kept; in the window this leaves eframe's device and the main viewport's GPU state alone, and in `--screenshot --serve` it works the same way. Tileset textures are uploaded again only when `Document::images_gen` changes (a new document, a tileset PNG hot reload, a tileset definition change); the chunk scene is rebuilt per snapshot (only the chunks in frame are built). The view's layer visibility and opacity apply (or only `layers`); entity boxes when `overlays`. `worlds --snapshot` calls the same `SnapshotRenderer::render`.

## Rendering

World and level are one space: each level draws at `world_px`. The camera maps world pixels to physical pixels as `world * zoom - round(origin * zoom)`, so at integer zoom every world pixel covers exactly `zoom` screen pixels. Overlays use the same snapped transform, and the pointer is hit-tested with its exact inverse, so the cell under the cursor is the cell drawn there at any zoom.

Below 4 screen px per cell, levels draw as flat egui rects with names. At and above it, the viewport adds one `egui_wgpu::Callback` that draws chunks:

- Every int_grid, tiles and auto layer of every level is cut into 32x32-cell chunks (`scene::Scene`). A chunk holds `Instance`s (40 bytes: world pos, size, texel UVs with flips as swapped corners, RGBA, layer index with the transpose flag in bit 31) in draw order, grouped into runs of the same texture. Int_grid cells use a 1x1 white texture and the value color. Tiles use a texture per tileset (Rgba8Unorm, nearest sampler, uploaded once at open and on hot reload).
- One GPU vertex buffer per chunk (`gpu::ViewportGpu`, instance-rate, grown to the next power of two). It is re-uploaded only when the chunk's `version` changed. A chunk is rebuilt only when it is dirty *and* about to be drawn, within a 6 ms per-frame budget (at least one per frame).
- A placement bigger than a cell, or offset by its rule, can reach into neighbouring chunks. The chunks of a layer split the plane into disjoint shares (their cells; the outer chunks extend to infinity past the level's edges), and such a placement is drawn in every share it overlaps, clipped to it (UVs cut to match), each chunk keeping the layer's global placement order. No two chunks of a layer draw the same pixel, so drawing chunk by chunk stacks exactly like drawing the layer as one list.
- Culling: each layer's extent (the union of its placements' quads; the level rect for int_grid) is recomputed from the actual placements after every invalidation. A level is skipped when no visible layer's extent meets the view, a chunk when its share of the extent doesn't, and then each chunk's actual instance bounds are tested.
- A frame is one `draw(0..4, run)` (triangle strip, instanced) per visible run. With one tileset per layer that is one draw per visible chunk per tileset. A layer that interleaves tilesets keeps its exact bake order by splitting into more runs.
- Layer opacity and visibility come from a uniform table (64 layers), so the opacity sliders never rebuild instances.
- **Flips and turns.** A tile's `flip` follows the export contract (`docs/format.md`, Godot's atlas transform): bit 4 transposes first, then bit 1 mirrors the drawn tile left-right and bit 2 top-bottom, in the destination; a quarter turn clockwise is `xt`, 180 degrees `xy`, a quarter turn counter-clockwise `yt`. Mirrors are swapped UV corners (`scene::tile_quad`). A transposed tile sets `Instance.layer` bit 31 and the shader reads the texture's `u` down the quad and `v` across it (it swaps the corner's axes before the UV mix, and masks the bit out of the opacity index), so with a transpose the x mirror swaps `v` and the y mirror swaps `u`, and the quad is the tile's height wide. The chunk clipper cuts a transposed tile's `u` by the share of the quad's height it keeps and its `v` by the share of the width (`Quad::clipped`). `eight_orientations_match_the_image_crate` checks all 8 against the tile turned with the `image` crate, pixel for pixel.
- Draw order: levels by `depth`, layers bottom-first as in `layers.json`, then entity boxes, grid, outlines and tool previews via the egui painter.
- Auto layers come from `worlds_rules::BakeCache::bake_detached` (every auto layer of a level, in dependency order), run at open on up to 8 worker threads (`Document::start_bakes`) and cached per level. When a bake arrives, that level's auto chunks are invalidated. After a rule edit, single (level, layer) jobs run on the same kind of threads (`Document::start_layer_bakes`); each arrival invalidates that layer of that level.

The draw path doesn't allocate: the visible list and draw list are reused `Vec`s. The paint callback carries no data and only binds and draws.

## Editing: the tool seam and the command layer

The viewport never mutates the document. Each frame it:

1. turns left-button gestures of the active tool into `ToolEvent`s: `Begin` (with a `Grab` for Select: the level body or a resize handle), `Move` (when the cell changes; for Select whenever the pointer moves), `End`, or `Cancel` (Escape, tool switch, reload). Every event carries `CellHit`s: level index, active layer index, cell in that layer's grid relative to the level the gesture started in (cells can go outside the level during a drag; `inside` says which), plus the world pixel. Painting tools don't start on a refused layer; they put the reason in the status bar instead. Space or the Hand tool pans instead.
2. exposes `Viewport::tool_input: Option<ToolInput>` (hover cell, drag start/current, grab, modifiers) for previews: brush footprint, rectangle (filled, or hollow with Shift), line cells, the resize outline with the new size.

After the dock is drawn, `EditorApp::frame` calls

```rust
commands.tool_events(&mut CommandContext { doc, view, invalidate }, &events)
```

once per frame (also with no events), applies the commands panels queued (`EditorState::pending`, one undo entry each), then forwards every pushed `Invalidation` to the viewport:

- `Cells { level, layer, rect }`: cells `[x0, y0, x1, y1)` of one layer (dirties the touched chunks)
- `Layer { level, layer }`: a whole layer
- `Level(ix)`: a moved, resized or re-depthed level (rebuilds its chunk grid; a move keeps the chunk ids and GPU buffers, a resize retires them)
- `All`: levels added, removed or renamed (rebuilds the scene)

The implementation is `edit::Editing`, installed with `EditorApp::set_commands` in `main.rs` (window) and `headless::screenshot`. It holds a `worlds_core::History` and a `worlds_rules::BakeCache`:

| Tool | Sends |
| --- | --- |
| Brush | `paint_cells` (int_grid) or `set_tiles` (tiles) for the Bresenham cells between the last two pointer cells, on every `Move`, inside one history gesture |
| Eraser | the same with `null` values, or `set_tiles` with `clear` |
| Rectangle | on release: `fill_rect`; with Shift, or on tiles, `paint_cells` / `set_tiles` of the clipped cells |
| Line | on release: `paint_cells` / `set_tiles` of the Bresenham cells |
| Fill | on click: `flood_fill` (int_grid); `set_tiles` over the same-stack region the editor computes (tiles); on a derived layer, `paint_cells` over the effective region |
| Select | `move_level` on release (snapped; the viewport previews the drag); `resize_level` on release with `anchor = -edges` (`tools::resize_command`, refused when it would strand an entity); crop to content (`tools::crop_command`) from the palette, menu and Inspector; plus `create_level`, `rename_level`, `delete_level` and `set_level_field` from the dialog, menu and inspector |

Every apply, undo and redo returns `Change`s, and they all go through `Editing::after`: `grid`/`tiles` changes become `Cells` invalidations, level moves and resizes `Level`, created/deleted/renamed levels re-index the document (bakes and the active level follow their level id) and `All`. The same changes go to `BakeCache::apply_changes`, which re-sweeps only the anchors within rule reach of the edit; `Document::bakes` and the cache share each layer bake (`Arc<LayerBake>`): before a re-sweep the document lets go of its copy so the cache edits it in place, then takes the updated one back, so a brush move costs what it re-sweeps, not a copy of the layer. Each returned dirty rect becomes a `Cells` invalidation of the auto layer. Since undo applies the entry's inverse through the same path, it invalidates and rebakes exactly what the edit did. Once the active level's worker bake is in, it is handed to the cache as is (`BakeCache::seed`, no re-sweep on the UI thread), so the first stroke is already incremental (about 0.15 ms per stroke step on a 32-rule layer, rebake included). If the worker bake hasn't arrived yet, or is stale (`Document::stale_bakes`: a tileset image or the layer's rules changed since), it isn't handed over and the first stroke bakes those layers on the UI thread. If a batch fails and so does its rollback (`CommandError::Rollback`, not expected in practice), the editor drops its caches, redraws everything and asks you to save and reload.

**Rule edits rebake one layer.** A `def` change of kind `rules` (layer L: `set_rule`, `remove_rule`, `move_rule`, `set_rule_group`, stamps, ...), `macros` (every auto layer whose rules use `rules/macros.json`: a reference, or a named pattern or legend) or `tileset` T (every auto layer that can draw from T, through rules, stamps, template references and level substitutions: `Project::auto_layers_drawing_from`) changes only those layers' bakes, so only they are rebaked, for a user edit, an agent write, undo and redo alike:

- the active level (and any level the same batch also edited) right away through the cache (`apply_changes` rebakes the layer in full), so the canvas and the Rules pane's counts show the edit the same frame;
- every other level: the cache forgets that (level, layer) (`invalidate_level_layer`), the document marks it stale (the old bake stays on screen meanwhile, and is never seeded into the cache or exported) and a (level, layer) job goes to one queue (`Document::start_layer_bakes`; the project is snapshotted once per edit), drained by at most `max_layer_workers` threads (the core count, up to 8) that start when there is work and end when the queue is empty, so twenty chance-slider ticks don't start a hundred threads. A worker checks the job's generation (below) before baking it and skips one a newer request superseded (`skipped_layer_jobs`). A result that comes back (`poll_layer_bakes`, once per frame) replaces that layer only, never the level's other layers, and if the command layer maintains that level it is handed to the cache as is (`Editing::adopt_layer_bakes`, only when the cache has nothing newer);
- each level gets `Invalidation::Layer { level, layer }`, never `All`, and no texture goes up again (a `tileset` definition change still re-reads the images and re-uploads the textures: `Invalidation::Tilesets`).

Out-of-date results are dropped by **generation**: every bake request (a worker batch, a layer job, a bake the command layer just stored) takes a fresh number, recorded per (level id, layer), and a worker result is stored only for the layers whose newest request is its own. So an older rule edit's job, a job overtaken by a paint in that level (the command layer bakes the layer itself then), or a whole-level batch from before a rule edit can never put an old bake back. A layer whose rules don't bake (a half-written rule) shows nothing rather than its old tiles, in the active level, in layer jobs and in whole-level worker bakes alike (a level's layers bake one by one there, so one broken layer doesn't hold back the others, and it isn't left stale for every export to retry). The cache's rebake goes on to the other layers when one fails (`BakeCache::apply_changes_per_layer`), so a macros edit that breaks one layer still shows the others' new bakes. `view.snapshot` first bakes any stale layer on the spot, so an agent never sees a level older than its last edit; saving with `export_on_save` bakes a level with a stale layer for the export instead of using its bake.

**Entity types and enums bake nothing.** A `def` or `def_renamed` of kind `entity` or `enum` (a user edit, an agent's `defs.*`, a disk change, undo and redo alike; the entity field definition commands `set_entity_field_def`, `remove_entity_field_def`, `rename_entity_field` included) and the project key `collision_layer` (it only matters to the export) leave every bake and the scene as they are: no `All`, no layer jobs, every `Arc<LayerBake>` the same. They bump `Document::defs_gen`, which the entity palette's rows are keyed on, and an entity type rename is followed in the palette's brush, favorites and recent. The project key `level_fields` (and so `set_level_field_def`, `remove_level_field_def`, `rename_level_field`) rebakes only the auto layers with a group reading a level field (`requires_level_field`), like a rule edit of those layers. An edit, undo or redo that takes entities away also takes them out of the selection.

Other definition changes (an agent's `defs.*`: layers, a tileset no auto layer draws from; a `def_renamed` of a layer or tileset) carry the per-layer view (visibility, lock, opacity, active layer) over by slug (following renames), re-read the tileset images when tilesets changed (`Invalidation::Tilesets`: the app uploads every texture again and restarts the watcher), rebuild the scene (`All`) and rebake every level from scratch through the cache.
